---
name: setup
description: "Set up the thread plugin: chat-only or the task board, your own stages, and whether that applies to every project or just this one."
argument-hint: "[--show] [--reset]"
---

Set the plugin up through a short conversation. Ask one question at a time. Use the question tool when this client has one, otherwise ask in plain text. Give the default choice first, with a one-line explanation of each choice. Do not ask anything the arguments already answer. Do not change any card.

1. Call the `config_get` tool and show the current settings in a few lines: the mode, whether waking is on, the stages in order, which stage each role uses, where each came from, and the two config file paths. If a file is marked as ignored, say so and why.
   - With `--show` in the arguments, stop there.
   - With `--reset`, ask which scope to reset (global, meaning the setting for every project, or project, meaning this project only), call `config_set` with that `scope` and `reset: true`, tell the user the result in a line or two, and stop. If this project keeps its board in the repo, warn them before the call and wait for a yes: a reset with scope `project` deletes the project's `config.json` in `.claude/thread/` (its mode, stages and roles), and once that is committed it is gone for everyone who uses the repo, not just on this machine. Offer to leave it and change the settings instead.
2. Otherwise ask, in this order:
   - Where the setting applies: every project (`scope: "global"`) or only this project (`scope: "project"`). Say that cards and threads are always stored per project either way.
   - What to use thread for: threads only (`mode: "chat"`: side threads, no task board; the board then has three fixed columns, New, Review and Done, whatever stages are set, and any stages they set are kept for the task board), or threads plus the task board (`mode: "tasks"`: cards, ideas and milestones).
   - Stages, only for the task board: the default six (Idea, New, In progress, Review, Blocked, Done), or their own. For their own, ask how they work in their own words, then propose a list of 2 to 10 stages. Give each a short id (lowercase letters, digits and underscores, starting with a letter) and a label of up to 30 characters. Say in plain words which stage each role uses: where a new card lands (start), where a running thread sits (working), where a finished turn waits for a look (review), where a failed thread sits (blocked), and where an ended thread goes, which is also, with the stages after it, what counts as finished for a milestone (done). For example "a running thread sits in Doing". Change the list until they agree.
   - Where this project's board is kept, unless `config_get` already says it is in the repo: on this machine (the default: cards are stored in the plugin's data directory), or in the repo (`repo: true`: the project's cards become files in a `.claude/thread/` folder at the root of the main checkout, with the project's mode, stages and roles in `config.json` there). Say in plain words what the second means: the folder is committed with the project, so the board follows it to every device that clones it and is the same in every worktree; the cards this machine has are copied there once (the old store is left as it is); threads, sub-agent runs, the wake setting and which cards Claude has seen stay on this machine; the files are visible to anyone with the repo, and the user has to commit them. A card that is started as a thread stays on this machine. Ask it as one plain question. It is a per-project choice, so it needs `scope: "project"`.
   - Waking: whether an answer to a waiting item, a "Report to main session" click or a "Notify Claude" click on the board should wake an idle session within a few seconds (`wake: true`), or reach it only with the user's next message (`wake: false`, the default). Ask it as one plain question and say in one sentence what turning it on means: the session then acts on its own, right away, which costs tokens while they are away and, in a session that skips permission prompts, runs without prompts; anyone who has the board link could start a turn that way.
3. Call `config_set` once with the agreed values (when they chose the repo, a second call with `scope: "project"` and `repo: true` if the scope above was global, or `repo: true` in the same call): `scope`, `mode`, `wake` (true or false), and for their own stages `stages` and `roles` together. For the default stages with `scope: "global"`, pass `stages: null`, which removes an older choice from that file. For the default stages with `scope: "project"`, pass the six default stages themselves (`idea` Idea, `new` New, `in_progress` In progress, `review` Review, `blocked` Blocked, `done` Done), because `null` there falls back to whatever the global file says. Report the result in a few lines and say they can run `/thread:setup` again at any time.
   - Turning waking on (`wake: true`) is never saved on the first call: `config_set` answers "CONFIRMATION REQUIRED" with a `confirm_code` and saves nothing, not even the other settings of that call. Set `wake: true` only when the user asked for it. Show them what it does (the sentence above), and call `config_set` again with the same arguments plus the `confirm_code` only after they agree. If they decline, call it again without `wake: true` (or with `wake: false`). `wake: false` needs no confirmation.
   - After `repo: true`, tell the user what the answer says (how many cards were copied, where the folder is) and that the `.claude/thread/` folder is theirs to commit. If `config_get` or the answer says cards on this machine's older board are not in the repo (an older plugin version in another session added them), offer `board_import`. Turning the repo board off is not a setting: they delete the folder by hand.
