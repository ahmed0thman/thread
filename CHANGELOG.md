# Changelog

Every release, newest first. The latest one is also summarised in the [README](README.md#latest-release); the documentation is in [docs](docs/README.md).

- **0.24.2** Every choice waiting item ends with an **Other** row: pick it and write your own answer (a single choice takes one option or Other, a multi choice any options plus Other). Claude gets your words first, `answered in their own words "…", and chose "A"`. They are also stored as the first entry of the item's options ("Other: …"), so a session on an older version still sees and delivers them; a board served by an older session refuses an Other answer and keeps your draft instead of dropping the words ([Waiting items](docs/reviews-and-waking.md#waiting-for-you)). A sub-agent run on a card shows its report again: current Claude Code ends a sub-agent with a `SubagentHandback` call and no final text, so runs recorded before showed "No report was recorded for this run"; the report is now the text handed back, else the last message as before ([Task and idea pages](docs/board.md#task-and-idea-pages)). Runs recorded before keep no report.
- **0.24.1** Lane work for a card shows on the card more reliably: the plugin's guide and `/thread:track` tell Claude to hand a card to a delegation lane with `thread_start` (`lane` and `card`) and never to run a delegate skill's relay itself from the shell, which the plugin cannot see, so the card showed a lane in its History but no run, no working indicator and no steps ([Running a lane for a card](docs/delegation.md#running-a-lane-for-a-card), and a new row in [Troubleshooting](docs/troubleshooting.md)); this is an instruction, not a check. The **Choose a worker** dialog no longer marks Claude (default) **Current** on a card with nothing saved while the field shows the last worker used: on the card's page the badge is **Saved** for the saved worker and **Picked** for one not saved yet, with no row marked when nothing is saved, and in the start step it is **Selected**; the dialog opens on the tab of the chosen worker, else of the one working now, else of the last one used ([Choosing a worker](docs/delegation.md#choosing-a-worker-on-the-board)).
- **0.24.0** Work on a delegation lane shows on its task card like a sub-agent run: `thread_start` takes `card` (`/thread:new --card c12`), and each turn of that thread records a run on the card with "code-codex working" on its face, the live steps, the prompt, the report and a link to the thread; the card stays a task, so its done gate holds ([Running a lane for a card](docs/delegation.md)). Codex and OpenCode lane turns show live steps for the first time, and Claude lanes now show them while the turn runs (agy shows start, stop and report). Claude is no longer shown the board's token in a tool result: `/thread:board` opens the board in your browser with a one-time code, Claude gets the address without the token, the page keeps the token so tokenless links open in any tab, the phone link is shown on the board (**Phone link**) instead of in Claude's answer, and stopping the board gives it a new token; an agent with a shell can still read the token from the data folder, so the gate is not a sandbox ([Security](docs/security.md)). Update notices: the install steps and `/thread:setup` tell you how to turn on auto-update, the first session after an update and the board say "Updated to X" once with a **What's new** panel, and an opt-in daily check (`updateCheck`, off by default) says when a newer release is out ([Staying up to date](docs/configuration.md#staying-up-to-date)). A local link such as a dev server on `localhost:3000` now opens in a new tab instead of moving the board to `#/`. The plugin's MCP server is declared in `plugin.json`, so the repository has no `.mcp.json` (which made Claude Code start a broken second server inside this repo).
- **0.23.0** A short README: what thread is for, install and a first use that walks the questions-and-review loop, what installing changes, a short tour, the limits (what Claude is instructed to do and what the plugin enforces), the evidence and an index; the full reference moved to [docs](docs/README.md) (one page per area), [CONTRIBUTING.md](CONTRIBUTING.md) is new and this file holds every release. A [demo](docs/demo.png) of the loop (a still and a 20-second GIF, invented data) and an [evidence page](docs/evidence.md) with the dated real Claude Code checks, including a smoke test of that loop on 0.22.0. `wait_add` now hands Claude the chat pointer ready made, "Waiting on you: c37.w2" with the id linked to the card's page on the running board, and the guide tells Claude to paste it as given, so you can click from the chat to the item. CI runs the suite on Node 20, 22 and 24 and the plugin validator on pushes to main and pull requests. The docs now say plainly that the done gate guards Claude's tool calls and is not a sandbox (an agent with shell access holds the board token).
- **0.22.0** Commands in Markdown text are shown as code blocks with a Copy button: a fenced block, or a line that is only one command in backticks, with the language as a label and a `$` before shell commands; Claude is told to put each command in a waiting item in its own fenced block. A bare `http(s)` address in text is now a link that opens in a new tab, and a link to a card on this board is the same reference as its id (without the access token). Claude is told how to use the board: the thread MCP server sends a short guide at session start (put each task on the board before starting it; every question, review or to-do for you goes through a waiting item with a one-line chat pointer; answers, card ids on sub-agent calls, moving and verifying cards), the session start note repeats the two main rules, and `/thread:track` loads before Claude starts a task or asks you anything; see [How Claude uses the board](docs/agent-behavior.md#how-claude-uses-the-board). `/thread:add` now takes `--bug`, `--idea`, `--priority`, `--label`, `--blocked-by`, `--agent` and `--criteria` besides `--milestone`, `--parent` and `--lane`, so you can add a bug or a task with its fields from the command. The Summary's time range has a **Last 7 days** option: the chart shows one point per day, the axis names each day and today, and the tooltip and table give the date. Every line of the [Milestones map](docs/board.md#the-milestones-view) can be named, and a drawn link or the card links behind a line removed, from a box on it.
- **0.21.0** The [Milestones map](docs/board.md#the-milestones-view) can be arranged (drag a milestone; the layout is saved on this computer, never in the repo; **Reset layout**) and linked by hand (drag its dot onto another: that one **depends on** it; a dotted "hand" line that counts for **Now**, **After** and `board_list` but never holds up a card). Keyboard: **M**, arrows, **Enter**. Claude sets links with `depends_on`. New: `dependsOn` on milestone cards (shared in the repo) and `milestone-layout.json`.
- **0.20.0** The Summary has filters (time range of 4, 8, 12 or 26 weeks, milestone, worker, type, priority and label, kept per project for the session, with a result count and Clear filters) that narrow every number on it, and its weekly bar chart is now a line chart of cards created, done and open at the end of each week, with a tooltip on hover or with the arrow keys, a legend with line styles and markers, and a table view. The [Milestones view](docs/board.md#the-milestones-view) is a map: the milestones in number order (`M0`, `M1`, … `M10`, whatever their state; done ones are no longer moved to the end), each a ring with its progress, linked by the dependencies their cards make (a card in one milestone blocked by a card in another), with the number of card links on each line. A line at the top says how many are done, which milestones you can work on now and what waits for you. Pick a milestone (click, or the arrow keys) to see what it depends on, what needs it, what is left before you reach it, which cards link it, and its counts and open cards. **Cards** shows every milestone as a block, as before, in number order.
- **0.19.0** The note on a card's page is a reading frame (the label **Note** and **Edit** in a header, larger text, coloured headings and bold leads, boxed code), and a card id (`c37`) or waiting item id (`c37.w2`) in any Markdown text is a [link](docs/board.md#card-and-waiting-item-links): hover or focus shows a small preview with a **Visit** button, a click opens the card and, for an item, scrolls to it. The `note` descriptions of `board_add` and `board_update` now ask Claude to write notes as short sections. The History on a card's page is a [timeline](docs/board.md#task-and-idea-pages): a marker per event, stage chips for a move, the worker as a chip, the time on the right, grouped by day, the newest 8 with **Show all N events**.
- **0.18.0** thread now describes itself as project management for AI agents: you manage the project, and Claude, its sub-agents, side threads and lane agents do the work (README, plugin and marketplace descriptions and keywords). Also opt-in, off by default: a new `codeMap` setting (`/thread:setup` asks, or `config_set` with `codeMap: true`) makes a thread's first prompt tell it to use the project's [Graphify code map](docs/threads.md#code-maps-graphify), when `graphify-out/GRAPH_REPORT.md` exists, as an index to find where to look, with a note that the code wins over the map and that an older map may be out of date. With the setting off, prompts are unchanged; thread does not run or read Graphify. The board's status shapes stay visible in high-contrast (forced colours) mode, and printing a view prints all of it instead of one screen. The plugin's permission check on its data folder walks the files once instead of at every start.
- **0.17.1** The card page's **Worker** field shows who works on the card, not only the saved worker: the sub-agent running now (`deep-analyst · working now`, or `3 agents working`), else the saved worker, else the last one Claude used (`deep-analyst · last used`), else Claude (default), with a caption for what **Start as thread** uses. The picker marks **Working now** and **Last used** rows, and the start step preselects the last worker used when no worker is saved and a thread can run as it.
- **0.17.0** The card's **Lane** select and the start step's separate **Agent** select are replaced by one **Worker** field: a button that shows the card's worker (`Claude (default)`, `agent: reviewer` or a lane) and opens a dialog, **Choose a worker**, with Claude (default) pinned on top, tabs for **Sub-agents**, **Project lanes** and **Global lanes**, one search over name, provider and model, badges for read-only, not approved, relay not installed and "overrides global", and full keyboard use. A card now holds a lane **or a sub-agent** (the new `agent` field, which an older version ignores; setting one takes the other off), and **Start as thread** runs the thread on the card's worker. Claude can set it with `agent` in `board_add` and `board_update`, and `board_list` shows `{agent: name}`. The start step tells the server which lane and agent it showed (`expectLane`, `expectAgent`), and the tunnel cannot set an agent, as it cannot a lane.
- **0.16.0** In a project kept in the repo, a **Notify Claude** click now wakes the session when waking is on. The click is written only to this machine's record of the repo's cards, which the waiter did not watch, so it reached the session only with your next message. You can now pick a card's lane on the board: a task or idea's page has a **Lane** select (None and the approved lanes, each with its provider and model; Save stores it), and the **Start as thread** step has a lane choice (**Claude (no lane)** or a lane) that is saved on the card when you press Start. A lane that is gone or not approved no longer blocks opening the step, so you can switch it there. The remote (tunnel) page cannot set, change or remove a lane; a save that carries one is refused.
- **0.15.2** A card shows when something is working on it right now. In the Board, the List, the Milestones view and a card's page, a pulsing dot with `worker working` (or `3 agents working`, or `Running on <lane>` for a thread) marks a card with a running sub-agent run or thread turn, so you no longer have to open an In progress card to find out. A run with no activity for 10 minutes shows as `quiet` in a muted style, so a run whose stop was never recorded does not look like live work. See [The Board view](docs/board.md#the-board-view).
- **0.15.1** Long text on a card page and a thread page is easier to read: a waiting item's text, a run's prompt, a thread's messages and the brief are shown with Markdown structure and the writer's line breaks, steps written inline ("1) … 2) … 3) …") become a numbered list, and a long message is clamped to about 12 lines with a **Show more** / **Show less** button instead of its own scroll bar. Tables in a report are drawn as tables, links show only their text (a file path is a dotted reference with the path in its tooltip, a web address opens in a new tab), headings are coloured (section names like Decisions, Risks or Next steps match the trace colours), and the note of a card or milestone is shown as Markdown with an Edit button. Paragraphs in a report now have a small gap between them. The `wait_add` tool tells Claude to put steps and lists on their own lines. `config_set` now says that the cards copied into the repo get new random ids and the old id still finds them. Milestones are listed by title with numbers in order (`M1`, `M2`, ... `M10`) in the Milestones view, the Summary, the milestone pickers and `board_list`, instead of by card id, which is random in a project kept in the repo.
- **0.15.0** A project's board can be [kept in the repo](docs/storage-and-sync.md#keeping-the-board-in-your-repo-claudethread): its tasks, ideas and milestones become files in `.claude/thread/` that you commit, so the board follows the repository to every device and worktree. Turn it on with `/thread:setup` or by creating the folder; the existing cards are copied once (with new random ids, so two devices never pick the same one), and `board_import` brings over cards an older session added later. Threads, runs and the `wake` setting stay on each machine. A git conflict in a card file names that file instead of breaking the board, and a card changed under a write is merged or refused, never overwritten. Only what you do on this machine's board carries your authority: an answer that arrived through a pull is passed to Claude once as information and never wakes the session, a pulled card shows as "new in the repo", and the done gate counts only approvals given here. An approval from another device, or one whose criteria have changed since, is accepted with one Confirm approval button, which confirms exactly what the page showed. A pushed file cannot replay an old approval, remove the criteria, undo a review you answered here, or fool the gate with a future date.
- **0.14.0** The Board and List filter bars are reorganized: search, filters and New card on one row; toggles, the waiting key and the result count on a second. Cards Claude has not seen have a Notify Claude action: it wakes the session you pick when waking is on, and otherwise reaches it with its next message. Answers to waiting items are drafts until one Send sends them all, so Claude gets them in one turn.
- **0.13.0** [Opening the board from your phone](docs/security.md#opening-the-board-from-your-phone-tunnel): `/thread:board --tunnel` opens a remote link through a Cloudflare quick tunnel (cloudflared installed once, no account), after asking you first. It lasts 12 hours, uses its own key, and cannot start, message, end or delete threads or stop the board. Milestones have no stage: a milestone is open until every card in it is finished, then done, and it reopens when a card is added; ideas do not count. Milestones are no longer on the kanban; the Milestones view, the List and the Summary show their state. A card in Done or any later stage (such as Released) counts as finished everywhere: blockers, counts, the Summary and the review gate. The new-card form has one **Type** select (Task, Bug, Idea or Milestone), and a task can be turned into an idea and back, keeping its bug mark, from its page or with `board_update`.
- **0.12.1** The Summary view is centred on wide windows instead of sitting at the left.
- **0.12.0** The board is a project manager. It opens on a [projects home](docs/board.md#projects-home-and-top-bar) with a tile per project, and each project has a top bar with a [Summary](docs/board.md#the-summary-view) (work analytics), the Board, a sortable [List](docs/board.md#the-list-view), [Milestones](docs/board.md#the-milestones-view) and Waiting, in place of project tabs; a switcher in the header moves between projects. Cards can carry a [type, a priority, labels, blockers and acceptance criteria](docs/board.md#card-fields-workers-and-the-done-gate), which you edit on the card's page and which show on the card faces and in `board_list`. Claude can say who did the work (`worker`) and the card shows **Worked by**; its history says who did each step. A card with criteria cannot be moved to done by Claude until you approve a review of it (a new approval is needed after the card leaves done, and a withdrawn review counts as closed), Claude can only add lines to criteria, and a card with criteria or blockers cannot be started as a thread. A done card without that approval is shown as not verified. [Waking the session](docs/reviews-and-waking.md#waking-the-session): with the new opt-in `wake` setting (`/thread:setup`), an answer to a waiting item or a click on **Report to main session** wakes an idle session at once, so it acts without waiting for your next message. Off by default, and turning it on through Claude needs your yes.
- **0.11.0** [Waiting for you](docs/reviews-and-waking.md#waiting-for-you): Claude puts a question, a choice, a to-do or a review on a card, a red pill shows how many wait on you, and you answer on the board; the answer reaches the session that asked with your next message. Task and idea cards open as a [workspace like a thread's](docs/board.md#task-and-idea-pages), showing the sub-agent runs Claude starts for the card (live steps, report, trace) and the card's history. Chat-only mode has three fixed columns: New, Review, Done. The board has a new look. Read threads now always run with `--permission-mode dontAsk` and cannot use edit tools or start sub-agents, whatever your own permission settings say; and the plugin's data folder is owner-only.
- **0.10.0** [Delegation lanes](docs/delegation.md#delegation-lanes): with the delegate skills installed, a thread can run on another coding CLI (codex, agy, opencode or claude) with the lane's model and effort, follow-ups continue that CLI's session, and a task card with a lane starts on it from the board. Cards show the lane and their page shows its details; `lane_list` lets Claude see and choose lanes. A thread report no longer shows a malformed step map as raw text.
- **0.9.1** A gear on every board card opens a menu of its actions (end or delete a thread, move a task to a stage, set its milestone, start it as a thread, copy a milestone's report) without opening the card. The board header shows the plugin version, and a note says when the page and the session serving it are on different versions.
- **0.9.0** Milestones: a card that groups tasks, ideas and threads, with a tag, progress, a board filter and a report (`/thread:board --parent`). Your own board stages and `/thread:setup` to choose them. A chat-only mode that turns the task board off. Follow-ups open with a "Since your last turn:" note when the main session has changed something the thread needs.
- **0.8.2** `/thread:board --stop` stops the board. A newer plugin version takes over a board served by an older one.
- **0.8.1** Task and idea cards open as a full page, like threads. The plugin has an icon.
- **0.8.0** Claude picks the sub-agent or model for a thread by how hard the task is. `--model` and `--effort` set them by hand.
- **0.7.0** Threads start from a brief instead of a copy of the session; `--full` keeps the copy. `--agent` runs a thread as a sub-agent. Token use is recorded per turn and shown on the board.
- **0.6.0** The board shows a thread's steps live, starts a card as a thread, and can queue a report to the main session.
